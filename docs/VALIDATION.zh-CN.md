## 2026-10-07：Windows、Linux、Android 与 ARM 验收

基线 `2d03031`，本次修改完成约定的现有环境验收。范围为 Windows、WSL Linux、API 21／28 构建在 Android API 34 模拟器中的执行，以及 QEMU 中的 ARMv7／AArch64 GNU/Linux。实体设备结果单列；Apple、旧 Windows、其他 libc 和远端 CI 不在本轮范围。工作流仅保留 `workflow_dispatch`，没有启动远端运行。

下表完整构建启用五种可选解析器、源码版 GNU libiconv、动态 OpenSSL、含 zlib／XZ／Zstd 的 libarchive，以及独立 7-Zip 26.04 后端，例外单独标明。公共头按 C99／C++11 独立编译，可选 C++20 测试也参与构建；自有 C++ 继续禁用异常。两种 Android ARM ABI 的最低 API 仍是 21，另以 x86_64 API 28 配置验证进程能力。

模拟器为 `Qt_Android_34`，Android 14／API 34，原生 x86_64，ARM64 使用 native bridge 转译，不支持 ARMv7 ABI。API 21 是构建下限，不等于在 Android 5.0 上运行过。没有把这些结果当作 APK 沙箱、ARM 实体板卡或硬件性能验收。可移植基准在共享宿主负载下运行，数值只作观察，不作为性能达标门槛。

API 21 的三项跳过分别是：模拟器 SELinux 拒绝路径 Unix socket、没有 Android 应用上下文时无法取得应用配置目录，以及低于 API 28 的进程捕获示例。API 28 保留前两项。IPC 和 C++ 平台套件记录 Unix socket 子项跳过后继续验证其他传输／功能，没有修改安全策略。交叉配置不注册宿主 Python 互通驱动，这部分由桌面矩阵单独覆盖。

通过目标运行确定并修复的问题：

- Android OpenSSL 使用自有 `shlib_variant` 配置、独立 `libssl-hx.so`／`libcrypto-hx.so` SONAME、相对 RUNPATH 和实际运行库清单。部署解析链接目标，排除会覆盖 native bridge 系统 BoringSSL 的链接别名，实际验证 Crypto 与 TLS 均可加载，不再以链接成功代替部署成功。
- 交叉依赖构建正确传递 NDK API／ABI、编译器及 sysroot。libarchive 显式使用指定目标 SDK；缺少 zlib、XZ、Zstd 或 OpenSSL 时构建失败。Android 实际运行 ZIP／密码 ZIP／7z／TAR／Gzip／XZ／Zstd 往返，以及可选原生后端的密码和文件名加密 7z。
- C99 解析器适配为 Bionic 补充私有静态断言，不修改 TOML 第三方源码。流的尺寸检查可以在 32 位编译。Android 23+ GNU `strerror_r` 按指针返回值处理，API 21 继续走 POSIX 分支。
- Linux／Android 压缩祖先目录检查在可用时使用仅要求搜索权限的描述符，仍保留 `O_NOFOLLOW`。新增只有执行／搜索权限的父目录回归；不再多余要求列出祖先目录。Android 测试去除写死桌面 `/tmp` 的假设。
- POSIX 示例验证并使用 main 的 argv，避免把 procfs 中转译启动器的参数当作业务参数；系统参数快照 API 继续报告操作系统观察值。明确 spawn 成功只保证创建子进程；测试 POSIX 允许的退出码 127 启动失败路径，不伪造 errno，不把它当作业务就绪。
- GNU/Linux 交叉构建使用 `HX_OS_SYSROOT=/` 时保留正确的绝对构建 RPATH。原生 7-Zip 支持目标工具链交叉编译；Android 线程符号取自 Bionic libc，并在该可选运行库内静态包含 C++ 运行时。
- Windows 并行运行暴露了测试夹具重名：两个压缩后端进程可能取得相同的粗粒度时钟值。临时目录名已加入进程 ID，之后全套测试及两个压缩用例并行重复 5 轮通过，不需要改变库的同步逻辑。

QEMU 限制通过完全不调用 hx_c_platform 的 `build-platform-probe/native.c` 复现：ARMv7 的 `sysinfo` 系统调用得到约 3.7 GB 总内存，但同一进程读宿主 `/proc/meminfo` 得到约 20.9 GB，本库没有换用另一指标来掩盖差异。进程测试已接受 POSIX 两种错误报告方式，但其刻意清空环境的子进程失去 `QEMU_LD_PREFIX`，无法找到目标动态加载器；带模拟器前缀的普通子进程／捕获示例通过。这些排除项不是库验收通过，仍需原生目标确认。随机数注入测试明确跳过不兼容的 LD_PRELOAD 场景，没有把宿主拦截库注入客体进程。

第三方来源统一为一个入口：默认 13 个固定提交的 Git 子模块，也可选择同提交 FetchContent；GNU libiconv 官方 Git 缺少生成转换表，因此使用带 SHA256 校验的官方发布归档。原 KCP／uthash 快照和旧缓存原样保留，除非显式选择，不参与当前构建。错误提交、缺失编解码能力的负向检查按预期失败，第三方工作区保持干净。操作见[依赖说明](DEPENDENCIES.zh-CN.md)及 [Android 命令](ANDROID.zh-CN.md)。

证据保留在忽略的构建目录：`build-platform-*-ctest.log`、`build-platform-*-accepted.log`、install／ABI／export 日志、`build-platform-probe/*.log`，以及 `build-platform-android-{x64,arm64,armv7,api28,minimal}/report*.json` 和逐程序 `run-*.log`。报告包含源码版本／未提交状态、NDK、构建 API／ABI、实际功能开关、设备指纹、原生／转译运行、部署的运行库及明确跳过原因。QEMU 运行 CTest 时设置 `QEMU_LD_PREFIX=/usr/<triplet>`，只采用已说明的排除项，不能整个平台一概跳过。脚本只清理已知上传文件，测试产生的剩余文件保留排查。

原生与独立进程测试覆盖多层中文／emoji 名称、Windows 长路径、空文件／空目录、空压缩流、连接 Gzip、Python 生成的 ZIP／TAR／Gzip／XZ、无后缀 7z 识别、错误密码、越界路径、已有链接、CRC／尾部损坏、不覆盖、指定文件提取、字节／深度／条目上限及取消。分配失败覆盖默认后端 100 个、原生桥接打包 180 个位置，父 context 最终分配计数归零。预期失败的子进程也会检查 sanitizer 诊断，不能把内存错误当成普通业务失败通过。并非所有第三方库都使用了编译器插桩，这些结果不表示证明了不存在任何原生缺陷。

集成中发现并处理的问题：

- Windows 的普通 7z 写入需要使用 libarchive 宽字符串入口；POSIX 元数据处理需要当前线程的 UTF-8 locale。原生 7-Zip 的 Unix COM 字符串是在 `wchar_t` 中存储 UTF-16 码元，包括代理项对。中文及补充平面的名字／密码均已验证往返。
- 固定版本 libarchive 的 Gzip 读取不校验尾部 CRC 和长度。自有流适配通过 zlib／liblzma／Zstd 校验完整流，并限制解码流大小，TAR 到达逻辑 EOF 后仍检查外层尾部。损坏尾部会失败，当前文件不发布，之前完成的文件按契约保留。
- ASan 检出了打包失败后过早进入 libarchive fatal 状态引起的压缩器内存泄漏。现在保留首个错误，把必要的原生收尾输出丢弃，并阻止临时文件发布；最后补充的条目上限场景还发现，跳过格式关闭会遗留 140 字节的 7z 目录元数据。已打开的写入器在标记条目失败后仍执行关闭，使原生所有权链完成连接，同时跳过未完成条目的填充。对应分配和容量失败场景通过泄漏检查。
- 并发销毁每次调用各自的 locale 时，TSan 报告 libc 转换缓存的分配／释放交叉访问。现改为并发调用共用不可变 locale，以短锁维护引用，由最后一个调用释放；编解码与用户回调期间不持有该锁。原始并发场景已在不使用抑制规则的情况下通过。
- TSan 还报告原生 7-Zip 全局缓存析构与另一调用的已结束工作线程之间缺少可见同步。可选后端现在使用私有、带顺序的卸载入口，在本库控制的模块引用释放之间建立明确同步；编解码与业务回调继续并行，诊断和注入分配器在锁外执行。对应并发用例连续五次通过，没有屏蔽规则。
- MSVC Debug 的静态压缩依赖需要匹配运行库，构建器增加 `HX_DEPS_CONFIGURATION=Debug`，Debug／Release SDK 使用不同 prefix。最初并行全量构建出现过没有进一步诊断的 CL／link 退出码错误，随后四路构建成功，未调整警告策略。

本机 7-Zip 25.01 命令行程序独立验证了生成的 ASCII 密码 AES ZIP、中文／emoji 密码加密 7z。Windows 7-Zip 的 ZIP 密码读取使用 CP_ACP，本机无法用它互读 UTF-8 非 ASCII 密码 ZIP；接口继续坚持 UTF-8，教程明确记录差异。该命令行程序只作为独立测试对端，不是库的回退实现。

实测公开类型大小／对齐（字节）：MSVC／GCC x64 的 options 为 136/8、result 为 56/8、entry 为 48/8；MSVC x86 分别为 96/8、56/8、40/8。私有栈上 job 为 x64 1,056/8、x86 904/8。数据按 64 KiB 分块处理，解压另有独立明文缓冲，外层解码再增加一个输出缓冲。原生字典、接口持有的分配和 7z 暂存文件不属于自有内存预算。进度记账使用每个操作自己的短锁，POSIX 默认后端进入／退出时另有两段 locale 生命周期锁；可选 7-Zip 后端在释放两个模块引用时增加短锁；普通动态库关闭不取得该锁。已有其他热路径没有增加归档锁、分配或分派。这是开销与布局记录，不是吞吐提升或 hx_c_log 性能达标结论。

日志位于共享构建、Win32、检查器及静态 SDK 构建的 `archive-*` 文件；裁剪使用 `build-archive-off-linux`，原生运行库构建器使用 `build-sevenzip-helper-*`。两端验证了路径与发布行为；macOS、Windows 7/8.1、Android、ARMv7/AArch64、musl 和真实板卡上的新增原生依赖仍待验证。TLS／加密共用的文件辅助代码已回归。此次 OBS 扩展清单的实现与示例已补到加密／TLS／压缩，目标环境的运行验收仍单独记录。

## 2026-10-07：标准 TLS 与分线程收发

基线 `7b43315`。新增可裁剪 C99 TLS 1.2／1.3 端点、不使用异常的借用式 C++11 包装、有界队列／peer、显式业务等待取消，以及可重试的正常关闭／中止。每个端点拥有一个 I/O 线程，服务端在其中管理多个 peer。OpenSSL 在该线程上通过有界 BIO pair 和既有原生 loop 工作，不给普通非 TLS I/O 增加锁或分发。旧公共布局保持不变，第三方源码未修改。

原生 C 测试覆盖同时双向各 1 MiB 传输、双向证书认证、错误主机名、系统信任拒绝私有测试 CA、部分数据后突然 EOF、取消后继续使用、48 个分配失败点、加密 PEM 密码，以及 peer 关闭超时／重试和 ID 不复用。独立 Python 客户端／服务端覆盖 TLS 1.2／1.3、三字节分片、多条 JSON 帧、过期证书、DNS 地址回退、背压／部分发送计数及关闭重试。Python 3.14 的严格验证发现初版测试证书生成器缺少密钥标识，已补齐 SKI／AKI，没有降低验证强度。C++ 测试要求关闭异常。OpenSSL 自身未完整加入 sanitizer 插桩，不能把这些结果视为对全部第三方内部路径的认证。

## 契约覆盖

- core：对齐和上下文所有权、UTF-8 错误、带状态的时钟读取、保留通知的事件、超时重试、线程 join 和 TLS key 生命周期。
- data：字符串自引用、复制／移动／格式化、非法边界、内嵌 NUL、 UTF-16 往返、严格错误／替换／进度；启用后验证 GBK、Shift-JIS、 EUC-KR、CP1252 向量；池上限／对齐／realloc／缓存、对象池／arena，文件追加／sync／短读／EOF 和目录重试。
- 路径：中文、补充平面字符、超过 260 字符的嵌套路径、非法 UTF-8 拒绝和资源清理。
- lifecycle：分配器故障注入与回滚、尚未结束的原生 TLS 析构、并发分配／realloc／collect，以及上游释放回调期间保持内存上限记账。
- pool：有界队列拒绝、排队取消、一次清理、超时保留、重试、任务句柄比池活得更久、拒绝同池自等待。
- net：本地 TCP 接受／连接／复制发送／接收／取消／截止时间，直接及异步 UDP 空数据报和截断、localhost DNS、定时器、投递、回调重入检查和请求句柄比循环活得更久。
- loop_concurrency：四个投递线程、2000 次完成回调、有界待处理工作、容量拒绝、零预算关闭定时器、关闭后拒绝准入。
- options：关闭的构造入口及传统编码明确返回 NOT_SUPPORTED。

尚未覆盖强制普通文件短写故障注入、磁盘写满／重启持久化、真实 UNC 服务、每一个代码页映射、休眠／唤醒、信号中断压力、全部原生网络提供方、外部 DNS 长时间停顿或真实宿主插件卸载。这些是目标验收任务，不能笼统藏在“已跨平台支持”中。

## 性能边界

可选 benchmark 目标已在 Windows 和 WSL 构建运行。其累计计时仅验证开发测量入口，不是受控验收数据或迁移前后性能结论。本轮没有进行基线扣除或 hx_c_log 接入性能测试。

| 路径 | 后续测量要关注的现有开销 |
|---|---|
| 原子操作 | 非内联 C 调用；原生 intrinsic／builtin；x86 CAS 循环 |
| 已有容量的字符串追加 | UTF-8 校验与复制，无池锁／全局锁 |
| 字符串自引用／格式化 | 可能需要临时分配 |
| 编码 | 标量校验；传统编码逐码点调用后端 |
| 文件 I/O | 原生调用，打开／查询时转换路径 |
| 事件 set/wait | 内部互斥锁、条件变量、保留谓词 |
| 内存池分配／释放 | 每池互斥锁，增长时才调用上游分配 |
| 任务提交 | 有界队列锁及任务／事件分配 |
| 异步请求提交 | 请求／事件／互斥锁分配，默认复制发送数据 |
| 循环驱动 | 对有界请求／截止时间线性扫描，使用原生等待后端 |

没有在缺乏证据时引入 SIMD 或手写大块复制汇编。 PAUSE/YIELD 和对应原子操作限制在底层。先在实际目标测量体积、吞吐、尾延迟、分配、锁竞争和系统调用，再决定是否引入定时器堆、请求存储复用或批量编码转换。 hx_c_log 锁定的五倍及单线程不回退门槛仍是后续独立验收。
