# 行为与生命周期契约

[English](CONTRACTS.md) · [README](../README.zh-CN.md)

**这页用来查“失败或超时后怎么办”。** 第一次使用请先运行[文件、配置或线程池教程](USAGE.zh-CN.md)，这里集中回答它们共同遵守的规则。

例如文件读取成功后，字符串由你释放，文件已经关闭；线程池等待超时后，工作可能仍在继续，不能先释放任务数据。判断一个调用是否完成，先看状态，再按该接口的实际完成量处理，最后决定释放还是保留资源等待重试。

## 共同规则

[Variant 值](VARIANT.zh-CN.md) 沿用这些所有权和错误规则，无需全局初始化，独立于不可变配置树和可变设置。clear 释放活动值但保留 context 持有，destroy 才释放这份持有。自定义描述符、代码和 user 数据按借用处理，需存活至所有关联对象释放；不建立全局注册表，也不自动阻止插件卸载。

状态值不是布尔值。OK 表示约定操作完成；EOF、NEED_INPUT、OUTPUT_FULL 分别表示文件结束、需要输入和输出容量不足。负值区分错误、超时、取消、暂时阻塞及容量限制。部分 I/O 后必须检查实际字节数。调用者可提供独立错误对象，保存统一状态、原生错误域／错误码及次级原因码。没有可变的线程全局“库最后错误”，也没有向日志器报告错误的回调。错误信息按 UTF-8 写入调用者缓冲区。

除非接口另有说明，输入指针只在调用期间借用，输出对象归调用者持有；销毁前必须排除新的使用者。创建失败不交付对象。不能用 free()、另一个库实例或另一个内存池释放对象。文档允许的 NULL 清理是空操作；关闭模块的构造入口返回 NOT_SUPPORTED。

下表中的创建／打开入口有一个明确例外：如果创建或打开失败，而且内部回滚也失败，会返回失败状态并保留非空 owner。错误信息仍说明创建失败的原因。这个对象只供清理，不能继续执行业务；保留它和分配器 context，使用下表中的既有接口重试清理。普通创建失败仍返回 NULL，不引入隐藏的回收线程，也不强杀线程。

| 保留下来的 owner | 继续清理的现有入口 |
| --- | --- |
| 线程池 | `hx_os_thread_pool_shutdown()` |
| 协程运行时 | `hx_os_coro_runtime_close_until()`，成功后再调用 `hx_os_coro_runtime_destroy()` |
| 目录监听 | `hx_os_watch_close_until()` |
| 协程 HTTP 服务 | `hx_os_coro_http_close_until()`，完成后再释放它依赖的 runtime |
| 进程输出捕获 | 在创建线程调用 `hx_os_process_capture_close_until()` |
| 共享内存 | `hx_os_shared_memory_close()`；创建／打开尚未成功时，data 为 NULL、size 为零 |

即使创建报错，也检查 owner 是否为空。目录监听创建失败不转移回调／cleanup 的所有权，保留原生 owner 的情况也一样。C++ 工厂返回失败的 `Result`，但调用者传入的 owner 变量仍保留资源，按相同规则清理；不要对失败的 Result 调用 `value()`。

状态、能力、时钟、Unicode 和原子接口不需要初始化。 NULL 上下文使用不可变的 malloc/free 策略。显式上下文复制分配器函数表，借用 user 数据，创建后不能更换。消费者的分配器生命周期不同，就各用一个上下文。空字符串也持有上下文；已分配对象同样使上下文保持忙状态。所有分配和持有关系结束前，销毁上下文返回 BUSY。销毁不能与新分配竞争，须先由调用者停止准入。

分配器回调需提供基础对齐、线程安全和跨线程释放能力。尺寸为 size_t；消费者传入更宽尺寸时必须先检查转换范围。库包装层提供更高的二次幂对齐，并记录原始分配器。回调代码和 user 数据必须存活到最后一次释放及上下文销毁成功。原生系统 API 与 iconv 可能使用自己的分配器；上下文控制本库分配，不控制全部系统／第三方后端内存。

## 时间与同步

等待接口接收绝对单调截止时间，单位纳秒，可由 deadline_after_ms() 构造。 NOW 用于轮询，INFINITE 表示无限等待；sleep_until(INFINITE) 非法。过大时长饱和到最大有限截止时间。单调时钟不计系统休眠，墙上时钟使用 Unix 纪元毫秒，可能跳变。纳秒单位不等于纳秒精度。 Windows 使用 QueryUnbiasedInterruptTime 满足休眠语义。带状态的时钟读取保留原生失败；便捷读取在单调时钟失败时返回 UINT64_MAX，墙上时钟失败时返回 INT64_MIN，此时构造截止时间得到 NOW。有限等待不会继续依赖无效时钟值。32 位 SDK 的 time_t 仍影响 2038 年之后的日期范围，有相应需求时必须选择并验证具备 time64 能力的 SDK。

已就绪事件或已完成任务可以在截止时间已过时成功。调度、耗时回调、重新取得互斥锁和原生操作退出可能延长实际返回时间。这些接口不承诺硬实时截止。

| 设施 | 共同保证 |
|---|---|
| 互斥锁 | 默认非递归，可显式选择递归；不保证公平性 |
| 条件变量 | 配合锁定一次的非递归互斥锁；不保留通知 |
| 条件等待 | 必须循环检查谓词；返回时仍持有互斥锁 |
| 自动复位事件 | 至多保留一次通知，由一个等待者消费 |
| 手动复位事件 | 保持就绪，直到调用者显式复位 |
| 线程 join | 同时一个 join 者；超时可重试；成功包含 TLS 清理 |
| 线程销毁 | join 成功前返回 BUSY；不 detach、不强杀 |
| TLS key | 正常退出时析构；存在活跃值时不能销毁 key |
| TLS 替换 | 不析构旧值；clear 才显式析构当前值 |

条件变量允许虚假唤醒。销毁互斥锁、条件变量和事件前，所有等待者必须退出。等待超时不使对象失效。线程 user 数据需存活到原生线程终止及 TLS 析构完成。 key 析构函数不能再次设置同一个 key。Windows 使用 FLS 完成退出清理；宿主若显式切换原生 fiber，值将表现为 fiber 局部存储。

原子类型提供对齐的 64 位整数和指针存储，发布前初始化，并发期间不能直接访问其成员，也不能放进 packed／未充分对齐的结构。即使只执行读取，原生 RMW 读取实现也要求存储可写。 load/store/CAS 的内存序限制见头文件，部分实现使用更强内存序。 GCC/Clang 使用 __atomic，MSVC 使用对应 Interlocked， x86 的 64 位更新通过 CAS 循环实现。能力查询区分是否无锁。不使用 volatile 本身代替同步。CPU 等待提示不提供内存序保证。

## 文件、路径与文本

文件对象面向普通文件，库自身不带用户态缓冲，系统／内核缓存仍存在。 read_some 以 OK 和正字节数表示读取成功，以 EOF 和零字节表示结束，错误单独返回；零长度读取返回 OK，不用于探测 EOF。 write_some 可只写入一部分。write_all 持续推进并在后续失败时报告累计字节数，不会对“成功但写入零字节”无限循环。重试时应根据业务条件只发送剩余后缀。

sync 通过 fsync／FlushFileBuffers 请求持久化，本对象没有 stdio 缓冲需要清空。共同契约不承诺硬件掉电安全或目录项持久化。文件调用可能阻塞，没有人为包装出的取消／截止保证。文件位置操作由调用者串行化。append 作用于每次原生写入，多次写入组成的记录不是一个原子事务。 close 即使报告错误也消耗句柄指针，不能重试可能已经复用的原生描述符。

路径为 NUL 结尾的 UTF-8，不隐式执行归一化、沙箱、locale 转换、大小写折叠或符号链接策略。POSIX 的非 UTF-8 文件名及 Windows 的未配对代理项文件名无法表示。Windows 内部转换到 UTF-16，并处理长绝对盘符／UNC 路径。 stat 显式选择是否跟随符号链接，特殊 reparse point 保持原生行为。移动限定同一文件系统，不偷偷复制再删除；不支持的原子不覆盖模式直接失败。目录删除要求为空。递归创建目录中途失败可能留下已创建的父目录。

目录枚举复制 NUL 结尾的名字，required 包含 NUL。 OUTPUT_FULL 保留当前条目以便重试。编码无效的条目会被消费并报告，调用者可显式继续下一个条目。EOF 表示枚举结束。

字符串始终拥有合法 UTF-8，修改需串行化。视图借用存储，不能跨越拥有者销毁或修改继续使用。 copy 保留目标上下文；move 转移源上下文，源变成使用默认上下文的空字符串。不能浅拷贝结构体。索引是码点边界上的字节偏移，不提供字形簇编辑、Unicode 大小写折叠、归一化或语言排序。

编码转换即使是 UTF-16/32 也以字节计长度，不插入、移除或猜测 BOM/NUL。 STRICT 不作有损转换；REPLACE 明确统计替换次数，使用 U+FFFD，目标无法表示时使用 '?'。输入输出不能重叠。 OUTPUT_FULL 时重试未消费输入；NEED_INPUT 时保留并重新提交不完整尾部。 final_input 区分分片未完成与最终输入截断。最终成功或严格错误后需 reset。error_offset 是流中的字节偏移， UINT64_MAX 表示没有转换错误。转换器不能并发使用。传统编码适配仅接受声明的无状态编码集合，不接受任意 iconv 名字或 ISO-2022。

## 内存池与异步任务

变长内存池默认可增长，maximum_bytes=0 表示不设增长上限。有限上限包含池控制的上游内存块、分配包装和元数据，不包含分配器私有记账或内核状态。尚未结束的分配／释放回调仍占用预算。 cached_bytes 单独限制整块空闲缓存，不存在绕过上限的隐式上游分配。释放必须回到原池；realloc 失败保留原块，槽位内尺寸变化可原地完成。存在活跃块时销毁返回 BUSY。对象池限制活跃对象数量；arena 由调用者串行化，reset 使全部分配失效。

线程池固定线程数和等待队列容量，默认 2 个线程、256 个等待任务。排队任务与正在提交的任务共同占用队列容量，运行任务另受线程数限制。拒绝提交不接管 user 数据。接受的任务会在工作线程调用一次 cleanup，包括排队后被取消的任务。运行任务需要主动检查取消标志。同一个池的工作线程等待该池尚未结束的任务返回 DEADLOCK。 wait 成功包含 cleanup 完成，任务结果与等待状态分开。任务句柄引用计数管理，可比已关闭的池活得更久。 close 选择排空或取消待处理任务，所有 join 共用调用者截止时间，超时保留资源，允许重试。

核心接口和创建事件循环不会启动后台线程。线程池仅创建指定的有限工作线程；异步 DNS 首次使用时才创建循环配置的有界解析线程池。没有退出宿主进程、强制终止线程或无人管理的 detach。

## 网络与事件循环

网络实例平衡原生初始化／清理，并持有套接字和循环的生命周期。基础套接字为非阻塞、不可继承，直接操作由调用者串行化。 TCP 接收区分 EOF 和零长度请求。UDP 零长度数据报仍是数据；截断返回 LIMIT 和复制字节数，剩余部分已丢弃。 IPv6 scope_id 显式设置；parse/format 只处理地址字面量，端口和 scope 留在独立字段中。DNS 接收 ASCII/Punycode 主机名，最多返回 256 个不同地址。

Windows 创建 socket 时指定 WSA_FLAG_NO_HANDLE_INHERIT。Linux／Android 在创建时设置 close-on-exec，并通过 accept4 同时设置 SOCK_CLOEXEC | SOCK_NONBLOCK；accept4 不可用时明确报错，不静默退回存在时间窗口的实现。POSIX 的 close-on-exec 表示执行 exec 时关闭，不会阻止 fork 暂时复制描述符。macOS 的创建／接受路径仍需单独调用 fcntl；如果要求隔离子进程继承，宿主需要协调并发创建 socket 与启动子进程的操作。

直接 connect_until 超时后连接建立仍可能继续，可关闭套接字放弃。 send_until 报告已发送前缀，已交付的数据不会回滚。就绪是提示，之后的非阻塞操作仍可能返回 WOULD_BLOCK。

客户端可能刚发起连接就退出。已知可恢复的 accept 错误返回 WOULD_BLOCK，并保留原生错误详情；循环的 ACCEPT 操作继续等待下一条连接，仍遵守原截止时间和取消请求。不会仅因一个待接入连接中止，就让整个 IPC／TLS 监听端点失败。监听器失效、资源耗尽等情况仍报告错误，不会把所有失败都无限重试。

关闭 socket 后，要同时检查返回状态和所有者指针。Windows 原生关闭失败时，保留 socket、网络引用和原有循环归属，允许重试。例如非阻塞 socket 设置非零 SO_LINGER 后，关闭可能返回 WOULD_BLOCK；此时不能丢弃所有者，也不能销毁它依赖的 network／loop。POSIX close 只调用一次：即使报错，描述符也可能已经被消费并清空所有者，因此不能拿旧的原生描述符再次关闭。

循环创建线程负责驱动、I/O 提交、附着套接字和销毁。该线程必须存活到循环销毁；原生线程 ID 可在退出后复用，不是全局唯一标识。 POST、请求取消／引用计数／等待可跨线程调用。每个套接字允许一个读方向和一个写方向请求同时存在； CONNECT 占用两者。不得混用直接 I/O 与待完成循环 I/O。套接字一直附着同一个循环，直到 close；繁忙套接字不能关闭。

操作描述、地址和 DNS 名字会复制。发送默认复制数据； SEND_BORROW 与接收缓冲区需存活到完成，user 借用到回调返回。接受的操作恰好在驱动线程回调一次，不持内部锁，不在 submit 内同步回调。提交失败不调用回调。默认上限为 1024 个请求、4 MiB 待处理缓冲／名字字节，另有受请求数约束的请求元数据；DNS 为 2 个线程、16 个队列条目。完成后仍由调用者保留的请求句柄占用调用者控制的内存，不再占用“待处理工作”预算。

回调可以提交新工作或关闭空闲套接字。递归驱动／关闭循环，以及创建线程等待未完成请求，返回 DEADLOCK。回调须正常返回，不能抛出 C++ 异常、longjmp 或在调用中卸载库。完成数据借用到请求释放；要取得新接受套接字／地址列表的所有权，需调用 take 接口，否则它们随请求销毁。请求 wait 成功包含回调返回，等待本身不驱动循环。

run_until 排空到空闲，poll_until 执行一批操作且可能等待工作。 run/wait 的截止时间不取消请求；操作自身的截止时间才请求取消，实际资源退出可能更晚。IOCP 取消后须收到原生完成包，才释放 OVERLAPPED 和缓冲区。POSIX 移除就绪监视不会撤销连接尝试。 CONNECT 失败／取消后应关闭套接字。 DNS 可能一直停留在原生 getaddrinfo 中；超时／关闭会保留其任务，不会提前释放数据或另起线程替代它。

close 停止准入、请求取消并驱动退出，期间可能执行回调。超时保留一切活跃资源。先让请求退出，再关闭附着套接字，最后销毁已关闭循环。已完成请求句柄可比循环活得更久。基础库没有固定两秒关闭策略。

Windows 投递 IOCP 唤醒失败时，会报告原生错误，不会永久屏蔽之后的唤醒。原生等待最多每隔 250 ms 检查一次这种失败；正常投递仍立即唤醒，内部检查不会制造对外的超时结果。这不是硬性响应时间保证。poll 报错不代表已接受的请求或缓冲区已经释放：继续驱动它们，或者调用 close。内部 DNS 线程池清理失败时，循环仍被持有且尚未完成关闭；再次调用 `hx_os_loop_close_until()`，完成后才能销毁。

## 链接和卸载

静态、共享消费者都必须通过创建对象的库实例释放对象。不能在不同插件私有静态库副本间交换拥有者句柄，也不能混用不兼容的 CRT／分配器函数表。使用 CMake 导入目标保持构建宏和传递依赖一致。

卸载插件／库前，要停止准入、结束任务和回调、join 工作线程及原生 TLS 清理、清空／销毁 TLS key、释放对象并销毁上下文。超时意味着尚不能卸载仍被引用的代码或 user 数据。 fork 后的子进程不能复用现有同步对象、池和循环，应 exec 或使用另行设计的 fork 后环境。没有接口被承诺为异步信号安全。
