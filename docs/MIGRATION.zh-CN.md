# 后续 hx_c_log 迁移方案

[English](MIGRATION.md) · [README](../README.zh-CN.md)

本文仅是方案。相邻 hx_c_log 源码只读参考，未作修改。它的私有平台头包含 hx_log.h，接受 sink／crash 配置，调用日志核心的分配／错误函数，并把 TLS 清理交给日志器。原样搬走这些文件仍然保留耦合，不能成为独立库。

可借鉴的经验包括不透明平台接口、单调截止时间、原子存储与操作匹配、UTF-16 路径、部分写入进度、原生线程退出清理和明确的能力开关。新库分别设计了错误、上下文和所有权。 OBS 衍生的警告 CMake 模块保留原 MIT 声明后复用。

## 通过薄适配映射

| 原私有操作 | 基础库接口／适配职责 |
|---|---|
| hx_atomic_load/acquire/store/release/add/cas | 显式内存序的 hx_os_atomic_* |
| hx_atomic_ptr_* / hx_cpu_relax | 指针原子操作／CPU 提示 |
| hx_mutex_* | 不透明互斥锁，保持原递归需求 |
| hx_event_create/notify/wait | 保留通知的自动复位事件及截止时间换算 |
| hx_thread_start/join/is_current | 线程入口包装、原生 join、独立销毁 |
| hx_mono_ms / hx_now_ms / hx_sleep_ms | 单调纳秒／墙上毫秒／睡眠截止时间 |
| hx_file_open / open_read / read_some | 文件标志，分离状态与字节数 |
| hx_file_write_progress | write_all 和 size_t 累计进度 |
| hx_file_flush(durable) | 先处理消费者缓冲，按需调用 sync |
| hx_file_size / move / remove / stat | 明确结果与统一／原生错误 |
| hx_make_directories / directory_scan | 目录接口，扫描策略继续留在上层 |
| hx_native_path / hx_wide_utf8 | UTF-8 路径接口／显式编码转换 |
| hx_tls_get/set | 消费者持有的 key 与消费者载荷析构 |
| hx_alloc / hx_free | 消费者独立上下文的分配器适配 |
| hx_network_* | 套接字／循环位于既有 framing、重试、sink 策略下方 |
| hx_platform_capabilities | 仅映射实际启用的基础能力 |

逐项迁移前检查语义差别。旧事件 wait 在截止时间已过时先返回，不会消费已有通知；新事件 NOW 可消费已就绪通知，适配层需保持日志器原行为。 join 与销毁对象分离。32 位消费者处理 uint64_t 长度时，必须拆分或检查大于 SIZE_MAX 的值，不能静默截断。

不同纪元或不同时钟语义的绝对截止时间不能混用。时钟构造和等待应一起迁移，或在适配边界换算剩余时长，不能简单把旧毫秒时间戳乘一百万。基础库不新增文件用户态缓冲，hx_c_log 保留自己的缓冲、输出顺序及轮转／持久化策略。

日期缓存、locale 稳定的数值格式化、控制台／系统日志 sink、正则行为、 fork 钩子、崩溃处理安装、LocalDumps 注册表设置、历史环导出和终止策略，仍留在消费者或未来明确的扩展中。原生调用栈与日志历史记录不同，本版不冒充这些操作已有通用替代。

## 阶段及验收门槛

1. 保存现有公共头／ABI、功能结果及锁定性能证据，固定负载、编译器、运行配置和文件摘要。
2. 增加可选基础库依赖及私有适配目标，保持 hx_log.h 和既有公共 ABI。
3. 先迁移状态／时钟／路径，再迁移文件、同步、线程退出和 TLS；每阶段都可单独回退和测量。
4. 网络基础操作迁移前保留 sink 的消息边界、重连、背压及关闭行为。不用通用线程池替代日志有序异步输出队列。
5. 验证格式快照、统一顺序、回调重入、分配器注入、所有权、重复初始化／清理及静态／动态安装使用。
6. 保留日志器默认 2 秒共用关闭预算。超时继续持有资源和 user 数据，允许重试；平台库只接收调用者截止时间，不对其他消费者固定两秒。
7. 在 Windows 与 WSL2 分别运行完全一致的锁定性能验收，通过后再切换默认适配并移除停用的旧私有实现。

hx_c_log 的性能验收使用包含最终持久化冲刷的三次完整运行中位数：八生产者吞吐至少达到锁定原版单生产者基线的五倍，新版单生产者不回退。冻结基线与详细测量记录保存在本地迁移材料中，这份方案不声称产生了新的性能结果。

同时报告提交延迟分位数、完成／丢弃／错误计数、排空时间、分配次数、新增锁／间接调用／系统调用及绝对吞吐。目录整齐或封装统一不构成性能证据。内存池接入、malloc_trim 和其他分配器实验须单独改动和测量，不混入迁移。

## 交付影响

消费者可使用 add_subdirectory 或已安装的 hx_c_platform::hx_c_platform 目标。独立安装的日志库若导出静态目标引用基础库，需在配置中 find_dependency(hx_c_platform)。静态传递依赖按配置包括 Threads、Windows 套接字及编码／原子库。共享包需携带匹配的 DLL/so/dylib，并保留实际包含的依赖许可证。

宿主和插件交换拥有者对象时，应使用同一兼容库实例。插件私有静态副本必须保有私有对象和配套分配器。回调、原生 I/O、线程局部析构或分配器 user 数据仍引用插件时不能卸载。
